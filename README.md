# OPEN / SHELF

<img src="assets/brand/logo.svg" width="88" alt="OPEN / SHELF logo">

**标识**：实心圆角方块取自「终端方块」——薄荷绿底承站点主色；左侧 `>` 是保留的终端提示符基因；右侧三条由长到短的横线既是「叠层抽屉 / 分门别类」的抽象，也像命令行里的多行输出。三款候选（书架 / 终端方块 / 叠层抽屉）中，最终采用后两者融合版。

一个简洁、带科技感的**个人收藏夹 / 私人数字宝库**。把常用的开源应用、写下的想法，以及预留给下一次灵感的位置，分门别类地收进同一个架子。纯静态、零依赖、零构建，直接托管到 GitHub Pages。

**页面结构**：三类页面，各司其职。`index.html` 是**产品介绍首页**，只做介绍——大标题、STATIC / MODULAR / NO BUILD 三个独立段落、功能模块的文字介绍、工作原理与收尾引导，不渲染任何可点击的模块入口卡片；`shelf.html` 是**收藏架页**，集中展示由注册表自动生成的全部模块入口卡片，首页的「现在开始收藏 / 进入收藏架」都指向它；每个功能作为二级页面运行在 `module.html?id=<模块id>` 上，互不干扰。首页采用居中的产品式排版：模块特点是无卡片的三段文字、工作原理是「序号 + 小图标 + 标题同行」的紧凑步骤（移动端不再被大图标台挤占篇幅），配合滚动入场动画；模块独立性并入 MODULAR 特点、本地/云端机制并入工作原理、功能细节并入收藏架卡片，收尾只保留一行引导。

**模块 01 · 开源应用**：提交一个 GitHub 仓库（`owner/repo` 或完整链接）并通过常驻的**分类筛选条**选择/新建目录（样式与模块 02 一致），页面自动读取项目介绍、Star、语言，以及**最新 Release 的版本号、发布时间与下载地址**。下载列表支持**按平台筛选**（Windows / macOS / Linux / Android / iOS），默认优先显示当前设备的安装包，最多显示 3 个主要安装文件（文件名、大小、下载次数），校验文件靠后；只看最新版本，无需切换。同时支持源码 `.zip` / `.tar.gz`、更新日志、一键刷新。内置**静态快照兜底**：API 限流或断网时依然显示内容。

**模块 02 · 笔记 / 博客**：用 Markdown 写教程与灵感，支持**图文、代码、内嵌视频**（B 站、YouTube、mp4 直链），按分类目录整理、全文搜索、标签归类。带左右分栏的实时预览编辑器、工具栏一键插入图片/网络视频/代码块；**可把本地图片直接拖进编辑区（或点「上传」选择），仅支持图片、禁止上传视频**，图片自动压缩、媒体单独保存，正文只留短引用，不干扰写作；视频请用「视频」工具贴网络地址。笔记保存在当前浏览器本地，可**导出/导入 JSON** 备份迁移。内置 3 篇示例教程，渲染器先转义后白名单注入，杜绝 XSS。

| 代码块 | 三个反引号包裹，可跟语言名如 ``` js |
| 列表 / 引用 | `- 项目`、`1. 项目`、`> 引用` |
| 视频 | 单独一行写 `@video https://…`（B 站 / YouTube / mp4 直链）；视频只支持网络地址，不能上传本地文件 |

> **上传限制与自动压缩**：**上传仅限图片，禁止上传视频**（视频请用 `@video` 贴网络地址）。源图最大 8MB，上传后自动迭代压缩（最长边 1600px 起、JPEG 质量 0.82 起，逐步降到体积目标约 260KB），GIF/SVG 与已经很小的图片保持原样。所有图片的总量限约 900KB——这是 GitHub Gist 单文件 API 只返回 1MB 的硬约束，超限会被截断导致同步数据损坏，因此同步层也会在写入前拦截超限数据、读取时发现截断立即报错。
>
> 媒体（data URI）单独保存在笔记的媒体字典里，**正文只插入 `![文件名](media:ID)` 这样的短引用**，编辑时不会被超长 base64 淹没；预览、阅读与云同步都会自动还原。旧版本正文里已有的 data URI 会在打开时自动迁移为短引用。取消编辑会回收未保存的媒体，导出 JSON 会连同媒体一起保存。网络图片/视频仍可直接引用地址。笔记正文与设置仅存在你自己的浏览器里，公开站点上的访客看不到彼此的内容。

**模块 03 · One more thing**：预留模块，只展示一个入口与说明页，不读写数据、不参与同步、不提供实际功能。它保留在注册表与模块切换菜单里，等以后有真正想做的东西时再填进去。

**跨设备同步（全自动）**：模块数据默认存当前浏览器；点页头系统状态图标旁的 ☁ 同步 按钮、填入 Token 并打开「自动同步」后，本地任何增删会约 2 秒后自动上传，其它设备每 15 秒自动拉取最新数据，多端保持一致，无需手动点按钮。**云同步一旦配置好 Token，模块 01 会自动匹配使用，不必再在模块 01 的设置里重复粘贴**；模块 01 设置里的 Token 只作为未开启云同步时的独立后备。嫌 Token 难记？可设一个自设口令把配置加密后存进「云端保险箱」，换设备时只需「用户名 + 6 位短码 + 口令」即可自动配好，记住的只有短码。详见下方「跨设备同步」章节。

**页头状态图标**：首页的 `SYSTEM`、模块页的 `MODULE` 状态标签已改为纯图标（右上角圆点仍表示在线状态，悬停可看提示）。点击模块页的模块图标会展开一个二级菜单，列出所有已注册模块并可一键切换；菜单项由模块注册表自动生成，新增模块无需改页面 HTML。

**明暗主题**：页头 GitHub 仓库图标左侧的圆形模式图标（纯图标，悬停可看当前模式）循环切换「自动 / 亮色 / 暗色」。默认自动：按本地时间在日出 06:00 至日落 18:00 之间用亮色、其余用暗色；手动选择会记住偏好。偏好仅存当前浏览器。GitHub 图标始终指向本项目仓库 `30-Chen/open-shelf`。

## 跨设备同步（全自动 · GitHub Gist）

解决「换设备 / 异地访问看不到自己数据」和「多端内容不一致」的问题。设计上是**本地优先 + 全自动同步**：数据始终先在浏览器本地读写（离线可用），后台自动与**你自己的私有 Gist** 对账，不改变站点零后端的性质。

**工作原理**：本地数据一变（约 2 秒防抖后）自动上传；页面打开的每台设备每 15 秒自动检查云端，发现变化就自动下载并刷新界面。两端几乎同时修改时按「修改时间戳较新者获胜」裁决（时间戳统一取写入方客户端时间，避免设备时钟与服务器时间不一致导致删除被云端旧数据覆盖）。面板标题行的**状态 / 自动合并胶囊**一边显示同步状态（悬停可看上次时间与最近检查结果），一边点击即可暂停或恢复自动同步；同步进行中胶囊内会出现一枚与文字等高的旋转箭头，完成后自动隐藏。

**内置示例不参与同步**：首次打开看到的示例项目/示例笔记是每个设备各自展示的演示数据，不是你的内容，因此不会上传到云端、也不会在多设备间来回覆盖。你一旦增删改（或云端有真实数据拉取下来），数据转为「用户数据」后才开始同步；所以删掉示例后，空清单会被同步，其它设备里的示例也会被清掉。

**第一步 · 生成 Token**

打开 <https://github.com/settings/tokens/new?scopes=gist&description=Open%20Shelf%20Sync>， scopes 只勾 **gist**（`gist: write`），生成后复制。也可以用面板里的「获取 Token ↗」直达。不需要 repo、workflow 等其它权限。

**第二步 · 首台设备配置**

进入任一模块（模块 01 或 02），点页头的 ☁ 同步 按钮，面板按两步组织：

- **① 连接云端**：粘贴上一步的 **GitHub Token**，点「**↻ 立即同步**」；自动开关已合并进标题行胶囊（默认开启），Gist ID 无需填写，首次同步后自动生成，需要时可展开「更多设置」查看/手填；
- **② 换设备**：先不用管，在首台设备只用它生成凭证（见第三步）。

标题行合并胶囊会显示「自动 · 已同步 / 有改动 / 同步出错」，发生跨设备合并时悬停可看到「已合并云端改动」；暂停时显示「自动已暂停」，未配置时显示「未配置 / 待关联」。之后所有操作自动进行：数据写进你账号下的一个**私有 Gist**（不公开、不出现在搜索里）的 `open-shelf.json` 文件。「立即同步」走与后台相同的智能对账，自动判断上传还是下载，不用自己选方向；「更多设置」里的**强制上传 / 强制下载**会跳过方向判断，只在冲突恢复时使用。

**重置到初始状态**（「更多设置」底部）：如果早期上传过超限大文件（图片等）导致 Gist 文件被截断、同步反复断流，可用它彻底重来，回到**完全未配置的出厂状态**。两级确认后按顺序执行：① 先停掉同步、作废在途请求；② 用当前凭证把云端文件重写为空（这一步必须用到 Token/Gist，所以只能在清凭证之前做）；③ 把本机两个模块数据清回内置示例；④ 最后清除本机 Token、Gist 关联与恢复凭证。重置后如需继续同步，要重新填 Token 或用凭证恢复配置。注意：① 云端清理失败时本机数据与凭证都不会动（避免两头皆空）；② 其它已关联设备需各自点一次重置，否则它们本地的旧数据会在下次对账时同步回来——不过只要那些设备本地没有新改动，即使不手动重置，也会跟随清空的云端自动清掉旧数据。此操作不可撤销。

**第三步 · 其它设备（推荐：6 位短码 + 口令，免记 Token）**

Token 又长又难记？用你自己设的口令把配置加密后存进一个**云端保险箱**，换设备时只记「**GitHub 用户名 + 6 位短码 + 口令**」，不用重新申请或抄写 Token。用户名是你自己的账号、口令是自己设的好记词，真正额外要记的只有 6 位短码：

1. **首台设备生成凭证**：在 ☁ 同步 面板的「**② 换设备**」区，切到「**生成凭证**」Tab，输入一个你自设的**口令**（至少 6 位，自己记牢），点「**生成凭证**」。面板会醒目显示一个 6 位短码（如 `K7M2QX`）和你的 GitHub 用户名，并自动生成「保险箱」。把「用户名 + 短码 + 口令」记进密码管理器（也可点「复制备用链接」一并保存）。
2. **新设备恢复**：打开站点点 ☁ 同步，在「**② 换设备**」区切到「**恢复配置**」Tab，填入**GitHub 用户名**、那 **6 位短码**、**同一个口令**，点「**恢复配置**」。Token、Gist ID 会自动填好并立即从云端拉取最新数据。之后自动同步照常工作。若短码定位失败，可在短码框直接粘贴备用链接恢复。

> 口令本身**不保存、不上传**，只用来加/解密；保险箱是一个**公开 Gist**，但里面只有密文，看不到明文 Token。用户名/短码泄露无妨（别人没口令打不开），口令忘了则无法恢复，请像保管密码一样对待。
>
> 备选：也可以不用保险箱，直接在其它设备手动填入**同一个 Token + 首台设备的 Gist ID**，效果一样。Gist ID 可在标题行合并胶囊的悬停提示里看到前 10 位，完整 ID 是 Gist 链接 `https://gist.github.com/<用户名>/<Gist ID>` 里最后那段。
>
> **旧版兼容**：旧方案生成的 `OS1.…` 长恢复码仍然可用——在恢复框粘贴旧码 + 输入同一口令即可，系统会自动识别。

**短码保险箱的安全实现**：Web Crypto `AES-GCM-256` 加密，密钥由口令经 `PBKDF2-SHA256`（12 万次迭代 + 随机盐）派生，每次生成都用新的随机盐和 IV。密文存进你账号下一个**公开 Gist**（文件名 `open-shelf-vault.txt`，格式 `OSV1.<salt>.<iv>.<ciphertext>`），description 里写入 `OSVAULT-<6位短码>` 标记用于定位。GitHub 没有按描述搜索 Gist 的 API，因此恢复时用「用户名 + 短码」列出该用户的公开 Gist 精确匹配，全程免 Token（公开 Gist 匿名可读）。密文不含明文 Token；口令错误或被篡改会解密失败并提示，不会写入错误配置。需 HTTPS 或 localhost 环境（浏览器 Web Crypto 的安全上下文要求）。

**关键行为与安全**

- **三方合并（three-way merge）而非盲覆盖**：每次同步成功后会把云端的模块快照存为「共同祖先」（`baseSnapshot`）。当本地和云端**同时**被改动时，不再用时间戳裁决谁覆盖谁（那会静默丢掉另一台设备新增的笔记/项目，且设备时钟不准时裁决还会错乱），而是以共同祖先为基准做结构化合并：
  - 对象按字段、带 `id`/`name` 的列表（笔记、仓库分组）按条目逐条合并；
  - 普通列表（分类、`repos`、置顶）按「任一端相对共同祖先删除就删除，否则取并集」处理，避免一端删掉的目录被另一端的旧列表重新带回云端；
  - 只有一端改了就直接用那一端，内容一致时什么都不做。
  这样三台设备交替增删最终都会收敛到同一份，谁的内容都不会被静默吞掉。同时保留「当前页面未打开的模块」数据，所以只在笔记页操作也不会丢掉开源应用的数据。
- **冷数据同步**：即使停在首页（没进入任何模块），后台也能同步——未挂载模块的数据直接读写 localStorage，进入模块时自动生效。
- **同步状态**：标题行胶囊显示同步状态（已同步 / 有改动 / 已合并云端改动 / 出错），悬停可看最近检查结果，出错不会静默。
- **新设备首次关联以云端为准**：本设备第一次连上某个云端 Gist（`syncedHash` 为空，含短码恢复后的新设备）时，无条件下载云端数据覆盖本地并建立共同祖先，不参与合并裁决——否则新设备较新的本机时钟会把本地示例/空数据误判为「更新」而上传，冲掉云端原有数据。之后各端正常做三方合并。
- **自动开关**：关闭后停止一切后台同步，本地数据保持不变；`visibilitychange` 时（切回标签页）会立即检查一次。
- Token 与 Gist ID 只保存在**当前浏览器**的 `localStorage`，不写进仓库、不发给任何第三方；点「断开关联」会清除本机保存的 Token 与云端关联、停止后台同步，模块 1 的本地数据保持不变，模块 2「笔记」则恢复为内置示例（回到未开启云同步时的初始内容）。
- 口令不落盘：保险箱只存密文，口令仅在当前页面内存中用于加解密，刷新即消失。
- Gist 里只有你添加的分类、项目清单、笔记正文与分类，**不含 Token、API 设置等本地偏好**。
- 同步失败会显示具体原因（Token 无效、缺少 gist 权限、网络不通等），标题行的合并胶囊会变红提示。

**六种状态下的数据归属**

| 状态 | 本地数据 | 云端 Gist | 处理方式 |
| --- | --- | --- | --- |
| 初始未设置云同步 | 正常读写浏览器本地存储；内置示例只是演示 | 不存在 / 未关联 | 没有 Token，后台同步不启动 |
| 开启云同步 | 与云端对账后保持一致 | 首次同步自动创建私有 Gist；之后双向同步 | 新设备首次关联以云端为准；之后以云端快照为共同祖先做三方合并，双方都改也不丢数据，上传前合并未打开模块 |
| 断开关联 | 模块 1 原样保留；模块 2 恢复内置示例 | 保留最后一次同步的内容，不再被本机访问 | 清除本机 Token / Gist ID / 同步哈希，停止后台同步；模块 2 清掉冷数据并回到示例态，重新关联时不会误判为「断开后的本地改动」 |
| 断开关联后新增 | 继续写本地，不会上传 | 仍是断开前的内容 | 通过快照哈希识别出「本地后来改过」 |
| 恢复配置 | 不再被静默覆盖 | 等待用户选择 | **同设备且有断开后新增**：面板出现选择卡——「上传本地」（本地替换云端同模块）、「下载云端」（云端替换本地改动）或「稍后处理」（两侧都不动，下次同步再问）。真正的新设备没有断开快照，仍以云端为准。 |
| 重置到初始状态 | 两个模块清回内置示例；Token / Gist / 恢复凭证全部清除，回到未配置状态 | 文件重写为空（旧超限内容被替换） | 两级确认；停同步→用凭证写空云端→清本地→最后清凭证；云端失败则本地与凭证都不动；其它设备各自重置或跟随空云端自动清空 |

> 注意：「上传本地」是按**模块**替换的——断开期间你在笔记里新增的内容会完整上传，但云端同模块的其它改动（如果别的设备也改过）会被本地版本替换。选择前请确认另一侧没有需要保留的新内容。

> 延迟说明：这是**准实时**（约 2~15 秒级），不是毫秒级推送——GitHub Gist 本身不提供 WebSocket 订阅。对单人多设备的「保持最新」场景足够。同一 Gist 只应由你自己的设备使用，不是多人协作方案；若需真正实时 + 账号体系，再考虑接入云数据库。

## 快速开始

```bash
# 本地预览（推荐）
python3 -m http.server 8000
```

## 数据源与限流

- 调用两个公开接口：`GET /repos/{owner}/{repo}` 与 `GET /repos/{owner}/{repo}/releases?per_page=N`（自动排除草稿，稳定版优先、预览版靠后；页面只展示最新版本）。
- 未认证时 GitHub 限制 **60 次/小时/IP**。页面内置 30 分钟快照缓存 + 请求缓存 + 并发上限 3，正常浏览几乎不会触发限流。
- 点击右上角 **⚙ 设置** 可填：
  - **GitHub Token**（可选）：限额提升到 5000 次/小时，填一个无权限的只读 Token 即可。**若已开启云同步，这里会自动匹配云同步的 Token 并禁用输入框，无需重复填写**；云同步 Token 变更时会即时跟随。未开启云同步时仍可手动填写，作为独立后备；
  - **API 地址**（可选）：访问 `api.github.com` 不畅时填可用的镜像地址。
- 设置只保存在当前浏览器，**不会写进仓库**。公开站点请勿填写带写权限的 Token。
- 请求失败时会保留上一次缓存数据并提示重试；仓库从未发布 Release 时显示「暂无发布版本」。

## 离线快照兜底（可选，建议保留）

浏览器直连 API 可能遇到共享 IP 限流、公司网络拦截或离线。仓库里附带一份静态快照 `data/snapshot.json`：

- 页面加载时**先读快照铺满首屏**，再用实时 API 覆盖（stale-while-revalidate），不会白屏等待；
- API 失败时保留快照内容，卡片底部标注「离线快照」并给出重试入口；
- 删除 `data/snapshot.json` 后功能完全正常，只是没有兜底。

更新快照（在项目根目录执行）：

```bash
node tools/update-snapshot.mjs
# 限流时可加 Token：GITHUB_TOKEN=ghp_xxx node tools/update-snapshot.mjs
# 临时指定清单：SNAPSHOT_REPOS="owner/a,owner/b" node tools/update-snapshot.mjs
```

脚本按 `defaults.js` 的清单抓取仓库信息与最新 Release，裁剪后写入 `data/snapshot.json`，提交到仓库即可生效。也可以在 GitHub Actions 里定时运行它，让快照始终最新。

```
  github.js                        数据适配层：输入解析 + API + 归一化

  index.js                         只注册元信息并渲染说明页，不读写数据
```

「互不影响」的四层保证：

1. 每个模块由内核创建独立 `<section id="module-<id>">` 容器；
2. 每个模块拿到的是**只属于自己的** `ctx.store`（key 前缀 `portal:v1:<id>:`）；
3. 样式强制使用模块私有前缀，不写全局选择器；
4. `mount()` 被独立 `try/catch` 包裹，某个模块报错只会显示自己的错误块，其它模块照常运行。

模块之间不直接引用，需要通信时走 `ctx.bus.on/emit`（例如 `net:response`、`sync:token-change` 事件）。云同步 Token 正是通过 `Portal.getSyncToken()` + `sync:token-change` 只读广播给模块 01，避免重复配置。

## 新增更多功能（示例）

已有模块 01 开源应用、模块 02 笔记，以及模块 03 的预留占位。以后想加「书签」「常用链接」等模块，只需要三步，不需要碰现有代码：

**1.** 新建 `assets/js/modules/links/index.js`：

```js
(function (global) {
  var Portal = global.Portal = global.Portal || {};
  Portal.registry.register({
    id: 'links',                       // 唯一 id，决定 DOM 容器与存储命名空间
    index: '02',                       // 引导页卡片上的编号
    title: '常用链接',
    desc: '收藏常用的网址，按标签整理。',   // 引导页卡片上的简介
    path: 'module.html?id=links',      // 引导页卡片的入口地址
    mount: function (ctx) {
      // ctx.root   独立容器
      // ctx.store  私有存储
      // ctx.net    请求层
      // ctx.bus    事件总线
      var list = ctx.store.get('list', []);
      ctx.root.innerHTML = '<div class="lk"><h2>常用链接</h2></div>';
    }
  });
})(window);
```

**2.** 新建 `assets/css/module-links.css`，类名统一用 `.lk-` 前缀。

**3.** 在 `shelf.html` 和 `module.html` 里按依赖顺序加脚本（模块脚本放在 `app.js` 之前），并在 `module.html` 额外引入模块样式：

```html
<!-- shelf.html：只需注册脚本，用于生成收藏架卡片 -->
<script defer src="assets/js/modules/links/index.js"></script>

<!-- module.html：注册脚本 + 模块私有样式 -->
<link rel="stylesheet" href="assets/css/module-links.css">
<script defer src="assets/js/modules/links/index.js"></script>
```

> 介绍首页 `index.html` 也保留全部模块注册脚本，目的是让停在首页时后台仍能对未挂载模块做冷同步；它本身不渲染入口卡片，无需新增样式。

内核会据此：在收藏架页 `shelf.html` 自动生成入口卡片，在 `module.html?id=links` 上只挂载这个模块。顺序、故障、存储都与其它模块隔离。
